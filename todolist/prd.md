## 1. 개요

### 1.1 목적
하루 동안 해야 할 일을 빠르게 적고, 체크하고, 정리할 수 있는 **가볍고 단순한 단일 페이지 웹앱**을 만든다.
설치·회원가입·서버 없이 브라우저에서 파일을 열기만 하면 바로 사용할 수 있어야 한다.

### 1.2 배경 / 문제
- 메모장이나 종이에 적은 할일은 완료 여부를 한눈에 보기 어렵다.
- 기존 할일 앱은 기능이 많아 "오늘 할 일"만 빠르게 관리하기엔 무겁다.
- "오늘"에 집중해, 하루가 지나면 자연스럽게 정리되는 흐름이 필요하다.

### 1.3 목표 (Goals)
1. 할일 추가부터 완료 체크까지 **3초 이내**에 끝나는 단순한 흐름
2. 새로고침하거나 브라우저를 껐다 켜도 **데이터 유지**
3. 오늘의 진행률을 **한눈에** 확인 (완료 개수 / 전체 개수, 진행률 바)
4. PC와 모바일에서 모두 편하게 사용 (반응형)

### 1.4 비목표 (Non-Goals)
- 여러 사용자 간 공유, 로그인, 서버 동기화
- 장기 일정 관리(캘린더, 반복 일정, 알림 푸시)
- 프로젝트·태그 기반의 복잡한 업무 관리

## 3. 핵심 사용 시나리오 (User Stories)

1. **할일 추가**: 사용자는 입력창에 할일을 적고 Enter를 눌러 목록에 추가한다.
2. **완료 체크**: 사용자는 체크박스를 눌러 완료 처리하고, 완료된 항목은 취소선으로 표시된다.
3. **수정**: 사용자는 항목을 더블클릭(모바일은 수정 버튼)해서 내용을 고친다.
4. **삭제**: 사용자는 삭제 버튼으로 항목을 지운다.
5. **필터**: 사용자는 전체 / 진행 중 / 완료 탭으로 목록을 걸러 본다.
6. **정리**: 사용자는 "완료 항목 지우기"로 끝난 일을 한 번에 정리한다.
7. **중요 표시**: 사용자는 별표로 중요한 할일을 표시하고, 중요한 항목은 위쪽에 정렬된다.
8. **하루 넘김**: 다음 날 페이지를 열면, 어제 끝내지 못한 일을 오늘로 가져올지 선택할 수 있다.

## 7. 데이터 모델

### 7.1 할일 항목 (Todo)
| 필드 | 타입 | 설명 | 예시 |
|---|---|---|---|
| `id` | string | 고유 ID (`crypto.randomUUID()` 또는 타임스탬프 기반) | `"a1b2c3"` |
| `text` | string | 할일 내용 (1~100자) | `"보고서 초안 작성"` |
| `done` | boolean | 완료 여부 | `false` |
| `important` | boolean | 중요 표시 | `true` |
| `createdAt` | number | 생성 시각 (ms) | `1793600000000` |
| `completedAt` | number \| null | 완료 시각 (ms) | `null` |
| `order` | number | 정렬 순서 | `0` |

### 7.2 저장 구조 (localStorage)
- 키: `todayTodo.v1`
- 값(JSON):

```json
{
  "version": 1,
  "date": "2026-11-02",
  "theme": "system",
  "todos": [
    {
      "id": "a1b2c3",
      "text": "보고서 초안 작성",
      "done": false,
      "important": true,
      "createdAt": 1793600000000,
      "completedAt": null,
      "order": 0
    }
  ]
}
```

- `version`: 향후 구조 변경 시 마이그레이션에 사용
- `date`: 마지막으로 사용한 날짜(로컬 시간 `YYYY-MM-DD`). F-32 날짜 변경 판단 기준
- 파싱 실패(손상된 데이터) 시 기본값으로 시작하고 콘솔에 경고

### 7.3 정렬 규칙
1. 중요(`important: true`) 항목 먼저
2. 같은 그룹 안에서는 `order` 오름차순
3. 완료 항목은 같은 그룹 안에서 아래로 이동 (P1)

## 8. 기술 설계

### 8.1 기술 스택
| 영역 | 선택 | 이유 |
|---|---|---|
| 마크업 | HTML5 (시맨틱 태그) | 접근성, 단순함 |
| 스타일 | CSS3 (CSS 변수, Flexbox) | 다크 모드·반응형을 프레임워크 없이 처리 |
| 로직 | Vanilla JavaScript (ES2020+, ES 모듈 미사용) | `file://`로 열어도 동작해야 하므로 단일 스크립트 |
| 저장 | `localStorage` | 서버 없이 데이터 유지 |

### 8.2 파일 구조 (예정)
```
todolist/
├── prd.md          ← 본 문서
├── index.html      ← 페이지 구조
├── style.css       ← 스타일 (라이트/다크 테마 토큰 포함)
└── app.js          ← 상태 관리, 렌더링, 이벤트, 저장
```

### 8.3 앱 구조 (app.js 설계)
상태 하나를 진실의 원천(single source of truth)으로 두고, 변경 → 저장 → 다시 그리기의 단방향 흐름을 따른다.

```
 사용자 입력(이벤트)
        │
        ▼
 actions (addTodo, toggleTodo, editTodo, deleteTodo, ...)
        │  state 변경
        ▼
 state { date, todos[], filter, theme }
        │
        ├──► storage.save(state)
        └──► render(state) ──► DOM 갱신
```

| 모듈(함수 그룹) | 책임 |
|---|---|
| `storage` | `load()`, `save(state)`, 버전 확인·손상 데이터 처리, 저장 불가 감지 |
| `state` / `actions` | `addTodo(text)`, `toggleTodo(id)`, `editTodo(id, text)`, `deleteTodo(id)`, `undoDelete()`, `toggleImportant(id)`, `clearCompleted()`, `setFilter(f)`, `carryOver()` |
| `selectors` | `visibleTodos(state)`, `stats(state)` → `{ total, done, remaining, percent }` |
| `render` | 헤더(날짜·진행률), 목록, 빈 상태, 푸터를 상태로부터 다시 그림 |
| `events` | 이벤트 위임: 목록 `<ul>` 하나에 click/dblclick/keydown 리스너 |
| `utils` | 날짜 포맷(`Intl.DateTimeFormat('ko-KR')`), ID 생성, 텍스트 검증 |

### 8.4 주요 처리 흐름
- **초기화**: `load()` → 날짜 비교 → (다르면) 이월 안내 상태 설정 → `render()` → 입력창 포커스
- **추가**: 입력 검증 → todo 생성 → `order` 부여 → 저장 → 렌더 → 입력창 비우기
- **수정**: 항목을 `<input>`으로 교체 → Enter/blur 저장, Esc 취소
- **삭제 되돌리기**: 삭제한 항목과 원래 위치를 임시 보관 → 5초 후 폐기

| AC-03 | 체크박스 클릭 | 취소선 표시, 진행률과 남은 개수 즉시 갱신 |
| AC-04 | 새로고침 | 할일 목록, 완료 상태, 중요 표시, 선택한 테마가 그대로 유지 |
| AC-05 | "완료" 필터 선택 | 완료된 항목만 표시, 없으면 빈 상태 문구 표시 |
| AC-06 | 항목 더블클릭 → 내용 변경 → Enter | 수정 내용 저장, Esc 누르면 원래 내용 유지 |
| AC-07 | 삭제 후 5초 안에 "되돌리기" | 원래 위치에 항목 복원 |
| AC-08 | 날짜를 넘겨 다시 열기 | 미완료 항목 이월 안내 표시, 선택에 따라 처리 |
| AC-09 | `<script>alert(1)</script>` 입력 | 스크립트가 실행되지 않고 글자 그대로 표시 |
| AC-10 | 360px 폭 화면 | 가로 스크롤 없이 모든 기능 사용 가능 |
| AC-11 | 마우스 없이 Tab/Enter/Space만 사용 | 추가·완료·수정·삭제·필터 모두 가능 |
| AC-12 | 다크 모드 시스템 설정 | 다크 테마로 표시, 명도 대비 AA 이상 |
